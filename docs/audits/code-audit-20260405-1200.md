# Code Audit: Dark Mode + Trial + Notifications + Card Redesign

Data: 2026-04-05 12:00

## 1. Podsumowanie (Linus Style)

Ocena: **Akceptowalne**

Solidna sesja — 4 feature'y w jednym ciągu: semantic colors, trial support, notification service, card redesign. Architektura ThemeExtension jest prawidłowa, trial model backward-compatible, notifications defensywne (try-catch, fire-and-forget). Główne ryzyko: duplikacja helpera `_cycleSuffix` w 3 plikach.

## 2. Krytyczne Błędy

Brak krytycznych błędów. Drobne uwagi:

- `notification_service.dart`: ID scheme `hashCode.abs() % 100000000 * 10` — teoretyczne ryzyko kolizji, ale przy <100 subskrypcjach nieistotne.
- `subscription.dart`: Duplikacja logiki `monthlyAmountFull` vs `_monthlyFromAmount` — te same switch-case. Kandydat do konsolidacji.

## 3. Sugestie Refaktoryzacji

### 3.1 Zduplikowany `_cycleSuffix`

Zdefiniowany w: `subscription_card.dart`, `dashboard_screen.dart`, `analytics_screen.dart`.

Proponowana zmiana: przenieść do `subscription.dart` jako extension na `BillingCycle`:

```dart
extension BillingCycleLabel on BillingCycle {
  String get suffix => switch (this) {
    BillingCycle.weekly => 'tydz.',
    BillingCycle.monthly => 'mies.',
    BillingCycle.quarterly => 'kw.',
    BillingCycle.yearly => 'rok',
    BillingCycle.custom => 'cykl',
  };
}
```

### 3.2 Duplikacja `monthlyAmountFull` / `_monthlyFromAmount`

Obie metody robią identyczny switch na `billingCycle`. `_monthlyFromAmount` przyjmuje kwotę jako parametr — wystarczy refaktoryzacja `monthlyAmountFull` by delegowała do `_monthlyFromAmount(amount)`.

### 3.3 `_NotificationSection` init pattern

`didChangeDependencies` z nullable boolami + null coalesce — uprościć do `late final` z `context.read` w `didChangeDependencies` lub `initState` z `WidgetsBinding.instance.addPostFrameCallback`.

## 4. Wnioski

Czy psujemy przestrzeń użytkownika? **Nie** — wszystkie nowe pola mają domyślne wartości, istniejące dane deserializują się bez migracji.
